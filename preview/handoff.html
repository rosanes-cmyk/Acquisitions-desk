What exists now

Database
15 sheets, exact headers, plain-text formats. setupDatabase() is idempotent and additive-only: it appends missing columns on the right and never reorders, renames or deletes one.
Client-callable surface
1 entry point. Every top-level function in Apps Script is reachable from the browser, so everything except api(), doGet and five guarded admin functions ends in _.
Actions
~45 registered against a whitelist, each mapped to one control on the card. There is no generic write action and no delete action, in any role.
Tier 1 tests
133 passing, plus two static checks that run on every npm test and block a push.
Tier 2 self-tests
17 cases written, DEV only, run from the Admin tab. Results land in a TEST_RESULTS sheet.
Tier 3 acceptance
Written click-by-click, including the cases a machine cannot run — two people in two browsers on the same lead, and the Manila / California same-day check.

Rules that are now enforced, not hoped for

  • Identity is the signed-in company account. No dropdown, no name field, nowhere to claim to be someone else. Every payload is stripped of caller-identity keys before a service sees it.
  • Nobody overwrites anybody. Every write takes a lock, checks the record version, and writes only the changed cells. A stale save is refused with the latest record attached, and nothing is written.
  • Nothing is ever hard-deleted. Leads are archived, users are deactivated, tool runs are voided. History sheets are append-only.
  • The company decides what "today" is. A rep in Manila at 2pm and a rep in California at 11pm the evening before write into the same business date.
  • Blank is not zero. A day with no speed-to-first-call entered is excluded from the average rather than dragging it to zero.

What only a person can do

Google requires a human for each of these. None of them can be done from a code sandbox, which is why the honest status is build complete except for human action rather than production build complete. Full detail is in RUNBOOK.md.

  1. Create the two script projects Owner account

    DEV and PROD, in a company-controlled Google account — never a personal one that disappears when someone leaves. Run clasp login as that account and paste each Script ID into the matching clasp config.

  2. Push, then set three script properties Developer

    ENV is the one to get right: it is what keeps the test functions away from real data. Leave DB_SPREADSHEET_ID blank the first time.

  3. Run setupDatabase() and click the consent screen Admin

    It builds the spreadsheet, every sheet, the formats and the seeds. Google's authorisation prompt has to be accepted by a person — there is no other route. Then run installTriggers() for the daily backup.

  4. Deploy, and keep the deployment ID forever Owner account

    Execute as Me, access Anyone within twinhomebuyer.com. Not "Anyone". Publish later changes by editing that same deployment — creating a new one silently changes the /exec URL and breaks every bookmark.

  5. Have a real employee open it Anyone but the developer

    They should see their own name in the masthead, and a LOGIN row with their email should appear in the audit log. If identity does not resolve, fix that before anything else. Then work the Tier 3 checklist.
